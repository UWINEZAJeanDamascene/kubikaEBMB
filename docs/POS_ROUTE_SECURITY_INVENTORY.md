# POS HTTP route security inventory

Generated from route declarations by `node scripts/check-pos-route-security.js --markdown`. Inventory: **221 route methods** across POS, till, legacy sales, credit-note, payment-settings, print-agent, and public-receipt routers.

This is a static route-middleware inventory. POS session and device labels prove identity bindings only; they do not prove that handlers scope every object ID to that company/register. Shift checks, controller validation, and resource ownership still require handler/service review. Rate-limit status records router middleware only; counters are process-local (see `docs/pos/route-rate-limits.md`).

## Review summary

- Authentication and authorization/replay scan: 221 routes; 0 missing declarations. 194 routes have explicit permission middleware and 27 use a documented action/protocol gate.
- Company/register identity at the router: 98 POS-session-bound, 12 device/protocol-bound, 111 require handler-level tenant review. This does not prove target object ownership.
- Shift-sensitive paths: 73 need handler/service review for open-shift and shift ownership; the session middleware itself does not require an open shift.
- Validation: 0 have a recognized route validator; 221 rely on validation that must be reviewed in handlers/services.
- Rate limits: 216 routes have router-level limiting; 0 have local PIN lockout only; 0 have no route-level limiter.
- Tighter limits: 4 credential-attempt routes share a 20-attempt/15-minute cap; 1 pairing routes use a 10-attempt/15-minute cap. Defaults are environment-configurable; counters are process-local.
- POS session middleware verifies active company, user, register, device, and session identity, and rejects a mismatched ERP tenant when both credentials are present. It does not enforce object-ID ownership or open-shift state globally.
- This report is a complete static inventory of the listed route declarations, not a runtime proof of controller/service behavior.
