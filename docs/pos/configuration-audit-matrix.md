## Structured audit fields

The current audit record stores typed `action_id`, `correlation_id`, `outcome`, `entity_type`, and `entity_id`, in addition to actor, company, register, event, metadata, and hash-chain fields. New rows use hash version 2, which hashes these structured fields. Existing immutable hash-version-1 rows are verified using their original representation and are not rewritten. Outcomes are database constrained to `COMMITTED`, `DENIED`, `FAILED`, or `OBSERVED`.

`action_id` identifies a specific emitted audit row; `correlation_id` groups multiple rows from the same workflow. Neither is an idempotency key by itself. Exact-once proof requires the operation's stable idempotency boundary and a test that asserts one committed domain effect and one completion event under retries/concurrency. That proof exists for sale completion and selected services, but not for every route in this matrix. The migration adding structured fields is intentionally not applied by this change.
